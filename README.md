一、项目背景
当前用户在进行自由行规划时，最大的痛点并不是“找不到攻略”，而是信息过载与信息割裂。用户通常会在多个软件进行信息收集。最终形成的问题是：用户拥有大量信息，却无法快速组织成一个真实可执行的旅行路线。
传统旅行攻略的问题在于，它们更像“景点清单”，而不是“真实旅行路线”。很多攻略会让用户在一天内跨越多个区域，忽略天气、排队、交通、疲劳感和临时变化，最终导致实际体验远差于计划体验。同时，现有地图产品只解决“导航”，并不解决“决策”；而内容平台虽然有大量真实体验，却缺乏结构化组织能力。
因此，我希望构建一个 AI 驱动的 Trip Planner，通过 AI Agent 自动完成从“碎片化旅行信息”到“可执行地图化行程”的全过程。产品最终输出的不只是攻略，而是一个可以在手机上直接打开、交互、分享、部署的旅行地图网页。
二、产品定位
 Trip Planner一款基于 AI 的旅行规划 Web App，核心目标是帮助用户从“碎片化旅行信息搜索”转变为“一键生成可执行旅行地图”。产品以地图为核心交互，通过 AI 自动生成多日行程，并结合地图导航、餐厅推荐、小红书、大众点评、天气提醒、交通衔接等能力，形成“规划 + 浏览 + 执行”的完整旅行体验。
三、目标用户
有明确目的地，但不想做复杂攻略，希望 AI 帮忙安排路线。
典型特征：
-  会看小红书 
-  会收藏餐厅 
-  但不会系统规划路线
四、产品核心逻辑
整个产品围绕三个阶段展开： Plan → Research → Build。
- Plan：
  - AI 会先解析用户输入中的硬约束，例如日期、酒店、航班、区域偏好等，然后自动把用户输入的偏好地点按照地理区域重新组织。
  - 整个规划逻辑强调“一天一个核心区域”，避免传统攻略中的高强度赶路。系统会优先保证旅行流畅度，而不是地点数量。
- Research：（待更新功能）
  - AI 会结合大众点评与小红书做本地生活研究。
  - 其中，大众点评主要用于帮助系统判断一家餐厅或地点是否真正值得去，包括排队风险、人均预算、本地用户真实评价以及是否存在明显“游客陷阱”等问题；
  - 而小红书则更多承担“体验层”信息补充，例如氛围感、最近用户体验、出片效果、情绪化反馈以及一些不会直接体现在评分里的软性避雷信息。AI 最终不会只给出“评分高低”，而是会结合路线、时间段与旅行节奏，输出真正有决策价值的推荐理由。
- Build：
  - 系统会自动生成一个单文件 HTML 页面。页面采用 mobile-first 设计，用户可以直接在手机上打开。页面核心由 Timeline 与 Map 组成，二者会实时联动。
  - 用户点击 Timeline 卡片时，地图自动 flyTo 对应地点；点击地图 Marker 时，页面会自动高亮对应行程卡片。整个体验会更像一个真正的 AI Travel Product，而不是传统网页。
六、技术方案
Trip Map Builder 采用“AI Agent + 静态前端页面”的技术方案，核心通过 AI 自动生成结构化行程数据，再渲染为可交互的旅行地图网页。
前端技术栈采用 HTML、TailwindCSS 与 Vanilla JavaScript，整体使用 mobile-first 响应式设计。地图能力基于 Leaflet.js 实现，用于完成地图渲染、Marker 展示与 Timeline 联动。
系统采用数据驱动渲染模式。AI 会先生成结构化 Trip JSON，包括酒店信息、每日行程与地点数据，再由 Renderer 模块自动生成 Timeline、地图、餐厅卡片与导航模块，避免页面内容写死，方便后续扩展与维护。
AI 工作流分为三个阶段：Planner Agent 负责行程规划与区域路线优化；Research Agent 负责结合 大众点评 与 小红书 做本地生活研究；Renderer Agent 负责生成最终 HTML 页面并完成交互绑定。
页面最终以单文件 HTML 输出，支持本地运行，同时可通过 GitHub 与 Vercel 自动部署，生成可公开访问的旅行网页链接。整体方案强调低成本、易部署与 AI 自动生成能力。
